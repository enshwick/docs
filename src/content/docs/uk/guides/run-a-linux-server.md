Виділений сервер Enshrouded існує лише для Windows. На Linux він працює під
Wine або Proton. Enshwick працює там з однією змінною середовища.

Кроки на цій сторінці виконано на збірці гри 26430253, під Wine 11.0 і
GE-Proton 11-9.

## Встановіть сервер з Enshwick

1. Встановіть виділений сервер через SteamCMD, застосунок `2278520`.
2. [Встановіть Enshwick](/uk/guides/install/) у теку, де лежить
   `enshrouded_server.exe`.
3. Запускайте сервер під Wine або Proton із `WINEDLLOVERRIDES="powrprof=n,b"` у
   змінних середовища. Тоді Wine і Proton беруть `powrprof.dll` від Enshwick.

Без цієї змінної Wine і Proton беруть власний `powrprof.dll`. Тоді сервер
запускається без Enshwick і без модів.

Оновлення через SteamCMD із `validate` перевіряє лише власні файли гри. Воно
лишає `powrprof.dll` і теку `mods`.

## Додайте змінну, коли хост уже задає її

`WINEDLLOVERRIDES` містить список, розділений крапками з комою. Якщо ваш хост
уже задає її, допишіть `powrprof=n,b` у кінець списку.

Наприклад, `dbghelp=n,b` стає `dbghelp=n,b;powrprof=n,b`.

## Перевірте, що Enshwick запустився

Відкрийте теку `logs` поруч з `enshrouded_server.exe`. Під час кожного запуску
Enshwick пише туди журнал `enshwick_<дата>_<час>.log`.

Його перший рядок називає версію Enshwick і версію Wine. Далі йде рядок на
кшталт `ready: 1 of 1 mods running`. Якщо такого журналу немає, сервер не
отримав змінну.

## Скористайтеся панеллю хостингу

Панель запускає сервер власною командою. Покладіть файли Enshwick у теку
сервера через файловий менеджер панелі або SFTP, а потім додайте змінну.

- **Pelican або Pterodactyl** з яйцем Enshrouded: поставте змінну перед
  командою запуску. Тоді команда починається з
  `WINEDLLOVERRIDES="powrprof=n,b" proton run`. Адміністратор змінює її на
  сторінці сервера в адмінській частині панелі.
- **AMP**: його шаблон Enshrouded уже задає `WINEDLLOVERRIDES`. Допишіть
  `powrprof=n,b` у цей список, як у розділі
  [Додайте змінну, коли хост уже задає її](#додайте-змінну-коли-хост-уже-задає-її).

Орендований сервер на Linux потребує тієї самої змінної. Якщо хостинг не дає
задати ні змінну, ні команду запуску, Enshwick там не запуститься. Орендований
сервер на Windows не потребує змінної.

## Візьміть ядро з ntsync

Запускайте Linux 6.14 або новіший із завантаженим модулем `ntsync`. Proton 11 і
GE-Proton 11 користуються ним без додаткових налаштувань. З ним очікування між
потоками гри займають значно менше часу.

1. Завантажте модуль: `sudo modprobe ntsync`.
2. Перевірте, що існує `/dev/ntsync`.
3. У контейнері передайте пристрій усередину, наприклад `--device /dev/ntsync`
   для Docker.

## Вимкніть налагоджувальний вивід Wine

Задайте `WINEDEBUG=-all` у змінних середовища сервера. Тоді Wine не пише
налагоджувальних рядків. Ці рядки забирають час на завантаженому сервері.

## Закріпіть сервер за ядрами

Дайте серверу власні ядра процесора, щоб інші програми не пересували його між
ядрами.

- Із systemd задайте `CPUAffinity=` у юніті служби.
- У Docker використайте `--cpuset-cpus`.
- Без них запускайте сервер через `taskset -c <ядра>`.

`WINE_CPU_TOPOLOGY` задає, які ядра бачить гра. Використайте його, коли гра має
бачити менше ядер, ніж є на хості.

## Дайте процесору працювати на повній частоті

Поставте регулятор частоти процесора `performance`, щоб ядра не сповільнювалися
між періодами навантаження: `sudo cpupower frequency-set -g performance`.

## Перевірте результат

Мод [Optimizer](/uk/mods/optimizer/) під час запуску пише один рядок у
свій журнал, `logs/enshwick.optimizer_<дата>_<час>.log`. У рядку версія Wine, ядро, знайдені
швидкі очікування, регулятор частоти і процесори, які побачила гра.

З ntsync там буде `/dev/ntsync present`. Для кожного налаштування, якого бракує, мод додає
пораду.

Про сервер у Docker або Kubernetes читайте
[Сервер у Docker або Kubernetes](/uk/guides/run-a-server-in-docker/).
